# المرحلة الأولى — التأسيس التقني والمعماري

**الحالة: مغلقة ضمن نطاق المرحلة الأولى.**

**نسبة إنجاز المرحلة الأولى: 100% من نطاق التأسيس المعتمد.**

هذا الإغلاق لا يعني اكتمال نظام القرطاسية التجاري؛ إنه يعني اكتمال الأساس التقني المحدد لهذه المرحلة فقط. لا توجد بعد نقطة بيع تجارية متكاملة أو محاسبة أو مشتريات أو دورة مخزون نهائية.

## سجل الاختبارات النهائي

- تشغيل GitHub Actions: `42901278746`.
- Windows: تثبيت الاعتماديات، Ruff، فحص سكربت PowerShell، 28 اختبار pytest، بناء Wheel، تثبيت الحزمة في مسار معزول، وإنشاء قاعدة البيانات وتشغيل النافذة وقراءة صنف اختبار — جميعها ناجحة.
- Linux: تثبيت الاعتماديات، Ruff، 28 اختبار pytest، بناء Wheel، تثبيت الحزمة في مسار معزول، وإنشاء قاعدة البيانات وتشغيل النافذة وقراءة صنف اختبار — جميعها ناجحة.
- لا توجد تحذيرات pytest في هذا التشغيل.
- أُزيل تحذير إعداد Alembic الذي ظهر في تشغيل سابق بإضافة `path_separator = os` ثم أُعيد الاختبار.

## حدود الاختبار وما لم يُدّعَ

- الاختبار على Windows تم في عامل Windows مستضاف على GitHub، وليس على جهاز المستخدم الفعلي؛ جهاز المستخدم لم يكن متاحاً وقت التنفيذ.
- سكربت التشغيل يثبت الاعتماديات عبر الإنترنت عند أول تشغيل؛ هذه ليست حزمة EXE مستقلة أو مثبتاً نهائياً.
- لا توجد بيانات منشأة حقيقية مقدمة من المستخدم؛ قاعدة البيانات تبدأ فارغة.
- مراجعة الأمان أولية وليست اختبار اختراق أو اعتماداً أمنياً. المخاطر المعروفة موثقة في تقرير الأمان، ويجب إغلاقها في المراحل الوظيفية ذات الصلة قبل البيع.
- خدمة البيع الحالية نواة برمجية للاختبار وليست POS مكتملة، ولا يجوز استخدامها في تشغيل تجاري.

## قرار الإغلاق

تُعد المرحلة الأولى مكتملة بنسبة 100% ضمن نطاق التأسيس التقني بعد نجاح اختبارات Linux وWindows، واختبار تثبيت الحزمة والواجهة، واختبارات النسخ والاستعادة، وتوثيق مراجعة الأمان.

لا يعني هذا القرار السماح بالانتقال إلى المرحلة الثانية تلقائياً في هذه الرسالة؛ المرحلة التالية تحتاج بدءاً مستقلاً وتبقى كل بواباتها خاضعة لنفس قواعد الإثبات.
